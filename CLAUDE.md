# youretfplan.com

- Edit only the sources in `src/`: `src/page.html` (main page) and one file per scenario page (`src/bank.html`, ...). Each is a claude.ai artifact fragment (no doctype/head) with markup, CSS and JS.
- Scenario pages are configured in `GROUPS` in `build.py` (localized paths, SEO title and description per language). Bank vs ETF: `/bank-vs-etf/`, `/it/banca-vs-etf/`, `/es/banco-vs-etf/`. Planned: buy vs rent and invest in ETFs, inheritance, own house (rent vs sell and invest in ETFs). The main page lists them under "What's your situation?" (`#cases`); a card becomes a link when its page exists.
- Wording (Marco): always say "investing in ETFs" / "investire in ETF" / "invertir en ETF", never just "investing".
- Then run `python3 build.py`. It writes `public/index.html` (English, `/`), `public/it/index.html` (Italian, `/it/`) and `public/es/index.html` (Spanish, `/es/`) with per-language SEO head (title, description, canonical, hreflang, Open Graph, JSON-LD) and pre-rendered text, plus `public/sitemap.xml` and `public/robots.txt`. Commit `public/` together with the source.
- All visible text lives in the `T` object in the script, with `en`, `it` and `es` entries. Every copy change must be made in all three languages. SEO titles and descriptions live in `build.py`.
- Language: on the site each language has its own URL (`<meta name="page-lang">`). On `/` the visitor is sent to their saved language, or on a first visit to the one guessed from time zone or browser language (Italy → `/it/`, Spain or Spanish browser → `/es/`); the EN/IT/ES buttons save the choice. Without the meta tag (artifact copy) the page switches language in place.
- Donations (Buy Me a Coffee, https://buymeacoffee.com/youretfplan) are switched off with `DONATIONS=false` in the script while Marco checks the tax side (Beckham regime). Set it to true to bring the button back.
- `worker/index.js` is the API (`POST /api/e` anonymous funnel steps, `POST /api/f` feedback), stored in the D1 database `youretfplan` (tables `events`, `feedback`, `salts`; created on first request). Visitors are a hash of a random daily salt + IP + user agent; salts older than today are deleted. No cookies. Tracking and feedback UI only run on the real site (page-lang meta present, not during the build pre-render). Scenario pages send `sc_<name>_view` and `sc_<name>_active` (plus `active`), and feedback with place `sc_<name>`. Funnel steps: view, hook (clicked "make my plan"), plan (reached the one-page plan), calc_seen, active (moved a slider in the 3 questions or the full calculator = active user), explore, start_seen, faq, bottom, feedback.
- Pushing to `main` deploys to production through Cloudflare Workers Builds (static assets from `public/`). Check both pages in a headless browser (phone width, light and dark) before pushing.
- Social preview images `public/og-en.png`, `public/og-it.png` and `public/og-es.png` are 1200×630.
